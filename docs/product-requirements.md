- 文档版本：v0.1
- 产品形态：Web 应用
- 项目阶段：MVP 需求基线
- 面向对象：产品设计、架构设计、Codex 开发、GitHub 协作与后续维护
- 暂定项目名：Earnings Radar
- 开源定位：GitHub 公开、支持自托管、可部署在线服务

## 1. 产品概述

### 1.1 产品定位

Earnings Radar 是一个面向美股投资者的公司事件监控 Web 应用。

系统围绕以下核心事件工作：

1. 财报预计发布日期；
2. 财报正式确认；
3. 财报日期变化；
4. 财报新闻稿发布；
5. SEC 文件提交；
6. 指数成分股加入；
7. 指数成分股移除；
8. 指数归属偏移；
9. 用户自选股重要事件；
10. 后续扩展的市场热度和 Reddit 讨论热度。

产品目标不是构建全功能金融终端，而是：

> 只告诉用户真正需要关注的公司、发生了什么，以及为什么这件事值得提醒。

### 1.2 产品核心价值

- 降低财报跟踪成本；
- 区分预计日期与官方确认日期；
- 及时发现财报日期变化；
- 将财报、SEC 文件和指数变化整合到统一事件时间线；
- 通过自选股和优先级减少无关提醒；
- 将指数加入、移除和偏移单独报告；
- 支持开源、自托管和持续扩展。

## 2. 产品目标与非目标

### 2.1 MVP 目标

MVP 必须实现：

- 可公开访问的财报信息页面；
- 用户注册、登录与自选股；
- 财报事件生命周期管理；
- SEC 文件监控；
- 四个基础指数成分股同步；
- 指数加入、移除与偏移报告；
- 财报和指数变化提醒；
- 邮件和站内通知；
- 管理后台；
- Docker 本地运行；
- GitHub 自动测试；
- 云端部署；
- 数据来源可追溯；
- 事件与通知不可重复。

### 2.2 MVP 非目标

第一版不开发：

- 实时行情终端；
- 期权链；
- 自动交易；
- 买卖建议；
- 财报后涨跌预测；
- AI 投资建议；
- 原生 iOS 或 Android App；
- Windows 或 macOS 客户端；
- 复杂 Reddit 情绪分析；
- 全量抓取 Reddit 评论；
- 财报电话会自动转录；
- 付费订阅系统；
- 全量复制 SEC 文档；
- 全市场无边界公司覆盖。

## 4. 股票覆盖范围

### 4.1 基础股票池

系统只监控：

- S&P 500 成分股；
- Nasdaq 100 成分股；
- Dow 30 成分股；
- Russell 2000 成分股；
- 用户手动添加的美国上市公司。

集合定义：

```text
S&P 500
∪ Nasdaq 100
∪ Dow 30
∪ Russell 2000
∪ 用户自选股
```

### 4.2 公司去重

同一家公司可能属于多个指数，但数据库中只能存在一条公司主记录。

优先使用：

```text
SEC CIK
```

作为监管身份标识。

股票代码用于：

- 搜索；
- 展示；
- 用户输入；
- 与市场数据源匹配。

### 4.3 监控状态判断

公司需要继续监控，当且仅当：

```text
属于至少一个启用指数
或
存在于至少一个用户自选股
```

### 4.4 公司退出监控池

当公司：

- 不再属于任何启用指数；
- 且不在任何用户自选股；

系统应：

- 停止同步未来财报；
- 停止市场热门计算；
- 停止后续 Reddit 热度统计；
- 停止普通提醒；
- 保留历史财报；
- 保留历史 SEC 文件；
- 保留指数变动历史；
- 保留通知审计记录。

## 5. 核心业务对象

### 5.1 Company

代表一家上市公司。

核心字段：

- 公司名称；
- 股票代码；
- CIK；
- 交易所；
- 国家或地区；
- 发行人类型；
- 财年结束月份；
- Investor Relations 链接；
- 当前监控状态。

### 5.2 Earnings Event

代表一家公司的某一财年、某一财季财报事件。

唯一逻辑建议：

```text
company_id
+ fiscal_year
+ fiscal_quarter
```

核心字段：

- 财年；
- 财季；
- 报告期结束日期；
- 预计发布日期；
- 正式确认日期；
- 财报发布时间；
- 盘前、盘后或未知；
- 电话会时间；
- 当前状态；
- 数据来源；
- 可信度；
- 创建时间；
- 更新时间。

### 5.3 Filing

代表 SEC 文件。

重点文件类型：

- 8-K；
- 10-Q；
- 10-K；
- 6-K；
- 20-F；
- 40-F。

核心字段：

- accession number；
- form type；
- accepted_at；
- period_of_report；
- primary_document；
- filing_url；
- exhibit_url；
- 是否与财报相关。

### 5.4 Index Membership

代表公司当前或历史指数归属。

核心字段：

- company_id；
- index_id；
- effective_from；
- effective_to；
- is_active；
- announcement_date；
- source；
- last_verified_at。

### 5.5 Index Change Event

代表加入、移除、迁移、修正或取消。

核心字段：

- company_id；
- index_id；
- change_type；
- announcement_date；
- effective_date；
- status；
- source；
- detected_at；
- previous_state；
- new_state。

### 5.6 Watchlist Item

代表用户关注公司。

核心字段：

- user_id；
- company_id；
- priority_level；
- is_active；
- created_at。

优先级：

```text
normal

```

### 5.7 Notification

代表一条待发送或已发送通知。

核心字段：

- user_id；
- event_type；
- related_object；
- priority；
- channel；
- status；
- idempotency_key；
- sent_at；
- error_message。

## 6. 财报事件生命周期

财报事件不是单一日期，而是一个完整生命周期：

```text
预计
→ 公司确认
→ 日期变化
→ 财报发布
→ 8-K 提交
→ 10-Q / 10-K / 20-F / 40-F 提交
```

### 6.1 财报状态

```text
ESTIMATED
预计

CONFIRMED
公司已确认

RELEASED
财报已发布

FILED
SEC 文件已提交

CANCELLED
已取消
```

日期变化不作为最终状态，而是生成独立变更记录。

### 6.2 财报类型

美国本土公司：

- Q1：通常对应 10-Q；
- Q2：通常对应 10-Q；
- Q3：通常对应 10-Q；
- Q4 与全年：通常对应 10-K。

外国私人发行人可能使用：

- 6-K；
- 20-F；
- 40-F。

### 6.3 财报时间字段

系统必须区分：

- `period_end_date`
- `estimated_release_at`
- `confirmed_release_at`
- `earnings_release_at`
- `conference_call_at`
- `filing_8k_at`
- `filing_periodic_at`

所有时间在数据库中统一保存为 UTC。

## 7. 财报数据来源

### 7.1 第三方财报日历

用途：

- 建立未来财报日历；
- 获取尚未确认的预计日期；
- 提供盘前、盘后等初步信息。

前端状态：

```text
预计
```

### 7.2 公司 Investor Relations 网站

用途：

- 确认正式日期；
- 获取电话会时间；
- 获取新闻稿；
- 获取演示文稿；
- 获取官方公告。

前端状态：

```text
公司已确认
```

### 7.3 SEC EDGAR

用途：

- 检测正式监管文件；
- 获取 8-K、10-Q、10-K、6-K、20-F、40-F；
- 判断财报是否发布；
- 保存监管原文链接。

前端状态：

```text
财报已发布
SEC 文件已提交
```

### 7.4 数据来源规则

每条关键数据必须保存：

- 来源类型；
- 来源名称；
- 来源 URL；
- 抓取时间；
- 是否官方；
- 原始响应；
- 可信度；
- 数据哈希。

原始数据和标准化数据必须分开保存。

## 8. 指数变化与偏移

### 8.1 指数调整中心

独立页面：

```text
/index-changes
```

页面必须包含：

- 待生效；
- 最近加入；
- 最近移除；
- 指数偏移；
- 自选股变化；
- 历史记录。

### 8.2 变化类型

系统必须支持：

```text
ADDED
加入

REMOVED
移除

TRANSFERRED
指数偏移

PARTIAL_EXIT
部分退出

FULL_EXIT
退出全部基础指数

MULTI_INDEX_ADDITION
新增多重指数身份

REENTERED
重新进入基础指数

UPDATED
调整修正

CANCELLED
调整取消
```

### 8.3 偏移识别

当同一家公司在相近时间发生：

- 一个指数移除；
- 另一个指数加入；

系统应合并为一条指数偏移事件。

示例：

```text
Russell 2000 → S&P 500
指数层级上移
```

```text
S&P 500 → Russell 2000
指数层级下移
```

```text
移出 Nasdaq 100，但仍属于 S&P 500
部分退出
```

```text
移出全部基础指数，但仍在用户自选股
退出基础股票池，继续监控
```

### 8.4 公告时间与生效时间

必须分开保存：

- announcement_date；
- effective_date。

页面状态：

- 已公告，待生效；
- 即将生效；
- 今日生效；
- 已生效；
- 已取消。

### 8.5 指数调整页面排序

默认排序：

1. 用户重点自选股；
2. 用户普通自选股；
3. 待生效；
4. 7 天内生效；
5. S&P 500、Nasdaq 100、Dow 30；
6. Russell 2000；
7. 已生效历史。

## 9. 提醒优先级

### 9.1 公司级别

```text
S 级：用户重点自选股
A 级：用户普通自选股
B 级：非自选的 Dow 30 / S&P 500 / Nasdaq 100
C 级：非自选的 Russell 2000
```

### 9.2 优先级原则

```text
用户主动关注
>
事件紧迫度
>
信息可靠性
>
指数重要性
>
市场与 Reddit 热度
```

### 9.3 事件紧迫度

优先顺序：

1. 财报刚发布；
2. 财报日期刚变化；
3. 财报相关 SEC 文件刚提交；
4. 24 小时内发财报；
5. 2 至 3 天内发财报；
6. 4 至 7 天内发财报；
7. 8 至 30 天内发财报。

### 9.4 提醒等级

#### P0：立即提醒

- 重点自选股财报发布；
- 自选股日期变化；
- 自选股 SEC 文件；
- 自选股指数偏移；
- 自选股退出全部基础指数；
- 重点自选股 24 小时内发财报。

#### P1：高优先级

- 普通自选股 24 小时内发财报；
- 自选股 2 至 3 天内发财报；
- 大型指数重要公司财报发布；
- 大型指数公司加入或移除。

#### P2：普通提醒

- 自选股 4 至 7 天内发财报；
- 非自选大型指数公司 24 小时内发财报；
- 热门公司临近财报。

#### P3：摘要

- 普通指数公司；
- Russell 2000 非自选公司；
- 尚未正式确认的预计日期；
- 距离财报超过 7 天。

### 9.5 默认通知策略

| 公司类别 | 默认处理 |
|---|---|
| 重点自选股 | 单独实时提醒 |
| 普通自选股 | 重要事件实时提醒 |
| Dow / S&P 500 / Nasdaq 100 非自选 | 每日摘要 |
| Russell 2000 非自选 | 网页展示或每周摘要 |
| 市场热门非自选 | 热门页面展示 |
| Reddit 热门非自选 | 热门页面展示 |

- 同步当前成分；
- 检测加入；
- 检测移除；
- 检测偏移；
- 生成变化事件；
- 更新监控公司池。

### 12.2 财报日历同步

频率：

```text
每天一次
```

职责：

- 获取未来财报；
- 创建或更新事件；
- 检测日期变化；
- 更新可信度；
- 记录来源。

### 12.3 SEC 文件同步

频率：

```text
每 5 至 15 分钟
```

职责：

- 获取最新文件；
- 匹配 CIK；
- 保存文件；
- 判断是否与财报相关；
- 更新财报事件；
- 生成通知。

### 12.4 IR 确认任务

频率：

```text
每 6 小时或每天多次
```

职责：

- 检查正式公告；
- 更新财报确认状态；
- 获取电话会；
- 获取新闻稿。

第一版只要求支持重点公司或有限的 IR Provider。

### 12.5 通知发送任务

频率：

```text
每 5 分钟
```

职责：

- 找到待发送通知；
- 合并摘要；
- 发送邮件；
- 生成站内通知；
- 记录结果；
- 失败重试；
- 防止重复。

### 12.6 健康检查

频率：

```text
每天一次
```

职责：

- 检查数据源失效；
- 检查任务长期未运行；
- 检查通知失败；
- 清理过期临时数据；
- 生成管理员告警。

## 15. 非功能需求

### 15.1 可维护性

- 使用 Django 模块化单体；
- 业务模块边界清晰；
- 数据源通过 Provider 适配器接入；
- 不在 View 中直接请求外部数据；
- 外部请求必须设置超时；
- 每个功能必须有测试；
- 配置使用环境变量；
- 数据库迁移必须提交 GitHub。

### 15.2 幂等性

重复执行任务不得产生：

- 重复公司；
- 重复财报事件；
- 重复 SEC 文件；
- 重复指数变化；
- 重复通知；
- 重复原始响应。

### 15.3 数据追溯

每条关键记录必须保存：

- 来源；
- 来源 URL；
- 抓取时间；
- 原始值；
- 标准化值；
- 旧值；
- 新值；
- 任务 ID；
- 操作人或自动任务来源。

### 15.4 安全性

- 密码由 Django 安全存储；
- `.env` 不上传 GitHub；
- API Key 只放云环境变量；
- 用户只能访问自己的自选股和提醒；
- 管理操作需要权限；
- 启用 CSRF；
- 输入必须校验；
- 日志不得记录密码和密钥。

### 15.5 时间与时区

- 数据库统一保存 UTC；
- 页面支持用户本地时间；
- 页面明确显示时区；
- 美东时间和用户本地时间可同时展示。

### 15.6 可部署性

目标命令：

```bash
git clone <repository>
cp .env.example .env
docker compose up
```

README 必须能够指导新用户完成部署。

### 15.7 可观测性

任务日志至少记录：

- 开始时间；
- 结束时间；
- 获取数量；
- 新增数量；
- 更新数量；
- 跳过数量；
- 失败数量；
- 错误原因。

MVP 上线后，优先验证：

1. 财报日期是否准确；
2. 财报日期变化是否能及时检测；

7. 是否存在重复提醒；
8. 财报季高峰期是否稳定；
9. 新用户是否能够自行部署；
10. 开源贡献者是否能理解项目结构。
