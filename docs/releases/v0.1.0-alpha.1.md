# v0.1.0-alpha.1 发布说明（草稿）

> 状态：**草稿**。本文随 Stage 8.2-B 实际部署时定稿并用于创建 GitHub Release；
> git tag 与 Release 本身尚未创建（8.2-B 由产品负责人按 `docs/deployment.md` 手工执行）。

## 这是什么

Earnings Radar 的第一个 alpha 版本：面向个人与受邀朋友的内部测试，**不按大规模公开服务设计**。功能范围以 `docs/development-roadmap.md` 阶段 0–7（MVP）为准；阶段进度以路线图为准。

## 测试数据范围与账号

- 测试对象限于产品负责人本人与受邀朋友，不公开宣传，不做搜索引擎收录优化。
- **公开注册关闭**：站点没有自助注册入口，账号只能由管理员在 Django Admin 创建或邀请（与 Stage 8.2 验收标准一致）。
- 测试数据为真实个人关注的美股公司与指数；审计与历史记录按 ADR-028 的保留策略维护（审计/领域历史永久保留）。

## 本版本包含的能力（MVP 摘要）

- 自选股与监控池、仪表盘与自选股页面；
- 财报事件全生命周期、日期变更历史与财报页面；
- SEC Filing 摄取与 Filing↔Earnings 链接分类；
- 指数变化识别与公开页面；
- 提醒规则（P0–P3 优先级）、站内通知与邮件投递、单条关键提醒；
- Django Admin 运维与手工修正、分离式健康检查（`/health/`、`/health/data/`）。

## 已知限制

- **IR 确认为 fixture-first**：真实 IR live 来源受 allowlist 与逐来源许可 gate 阻塞（ADR-022）。alpha 期间数据健康页的 IR 路由显示 `blocked` 属预期。
- **指数公告为 fixture-first**：指数成分来源与许可未确认（ADR-005），真实抓取为零网络；数据来自 fixture/replay 管线。
- **Alpha Vantage 财报日历未配置生产 key**：canonical/reference 日历同步没有生产凭据，数据健康页对应路由显示 `not_configured` 属预期。
- **通知延迟受平台粒度限制**：Railway cron 最小 5 分钟间隔且执行可能漂移数分钟，P0/P1 通知端到端延迟可能周期性略超 5 分钟（ADR-004 目标按可测样本 ≥95% 评估，详见 `docs/deployment.md` §10）。
- **完整每周摘要未包含**：单条关键提醒（站内与邮件）可用；完整每日/每周摘要不作为 alpha 开放条件，完整每周摘要未实现，计划在 beta（8.4）交付。
- **备份保留为平台近似映射**：ADR-028 的「每日备份、保留 30 天」由 Railway Daily/Weekly/Monthly 快照叠加近似（6/27/89 天）；逐日 30 天精确保留需自建对象存储管线，alpha 不做（`docs/deployment.md` §7）。

## 明确不包含的内容

本版本**不包含任何第二阶段能力**：市场热门、Reddit/Telegram 等社交信号、Web Push、PWA、自选股分组、Celery/Redis 任务队列、微服务与 SPA 均未实现；这些内容只存在于路线图的第二阶段规划中，本发布说明中的任何能力描述均不得理解为已实现它们。
